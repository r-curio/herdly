# Claude setup

Claude setup is explicit and scoped to one configuration root. The default root is `~/.claude`; an alternate root selected from **Agents → Claude Code** is kept independent. Steer never scans for accounts or credentials and never merges roots.

The preview and install own one packaged `SteerHook` copy, one set of hook entries in that root's `settings.json`, and ensure `env.CLAUDE_CODE_DISABLE_TERMINAL_TITLE=1`. Steer records that environment key as owned only when it had to add it; a pre-existing matching value remains user-owned and is preserved through repair and undo. The title hooks return Claude's supported JSON `terminalSequence` response: `SessionStart` sets `Steer Claude <full-session-id>` for exact Ghostty matching and `SessionEnd` requests a title reset. They never write the OSC sequence as plain hook stdout. Steer does not install a launcher, change permission rules, or restart Claude sessions.

The installed hook set observes session, prompt, tool, Bash permission, subagent, notification, stop, and session-end events for the later Claude intake slice. The Bash matcher is observation/setup only here; native Claude remains the fallback until the approval slice proves a direct decision path. The optional usage bridge is offered in the same preview and is off by default. Selecting it records the intent but does not edit `statusLine` until the compatibility probe passes; the core connection remains independent. This setup slice stores only event name, session identity, Steer source and installation identity, receipt timestamps, and Claude's SessionStart source. It does not persist prompts, commands, paths, reasons, tool input, or other event payloads before the later intake work.

The preview lists every affected `settings.json` field with its matcher, exact helper command, timeout, and owned environment value. It also lists the selected settings file, helper, event-record directory, install record, and backup directory. It does not display the complete `settings.json` or unrelated settings and credentials. Steer reads `claude agents --json` in a bounded subprocess with the selected `CLAUDE_CONFIG_DIR`, validates the top-level array, canonical full session IDs, nonempty shared `cwd`/`name`/`startedAt` fields, supported kinds, lifecycle fields, and duplicate identities, then keeps only typed restart status. It never uses `cwd` or `name` as identity or targeting evidence. An active session counts as needing restart only when it started before installation and has no newly observed startup delivery; sessions started after installation or already observed by the exact startup hook are not counted. A disabled, failed, timed-out, malformed, or incomplete inventory is reported as unavailable; Steer never treats it as an empty root, never persists the inventory payload, and does not write a new core setup until the selected root can be read successfully.

Steer configures the selected user root. Claude can also merge project and command-line settings, and the supported CLI does not expose a per-key effective-settings resolver. Steer fails closed for a detected `CLAUDE_CONFIG_DIR` mismatch or managed policy. Project context is not supplied to this setup snapshot, so project and command-line `--settings` values remain unavailable in the preview. The UI warns that arbitrary future project files or command-line `--settings` values may override the selected root; Steer does not claim those values are absent or inspect the app's working directory as a substitute. It requires a new `SessionStart` event from the exact selected root before reporting Connected.

## States

- **Not configured**: no Steer install record exists for the selected root.
- **Configured; restart required**: owned files are present, but Steer has not observed a post-install startup event from this root.
- **Connected**: a newly received `SessionStart` event whose Claude `source` is `startup`, carrying this root's installation identity, was observed after installation. Resume, clear, compact, or other events from another root, another installation, another hook event, or before installation do not connect the root.
- **Repair required**: an owned hook or helper is missing.
- **Conflict**: an owned value changed, duplicate Steer installs exist, or the install record is inconsistent. Steer does not overwrite it.
- **Blocked by policy**: managed settings allow only managed hooks, or hooks are disabled.
- **Shadowed**: a higher-priority settings source wins; Steer does not try to defeat it.
- **Unsupported**: the detected Claude Code version is older than the tested `2.1.273` baseline. Newer versions still need a fresh runtime event before they become connected.

Ghostty readiness is separate from connection health. A root can be connected while Ghostty controls are off or still awaiting Automation permission. Exact return remains unavailable for stale, duplicate, overwritten, split, cross-window, or otherwise ambiguous targets.

## Ownership and undo

Reinstall reuses the root's installation identity and recreates only missing exact entries. A changed owned handler or title environment value is a conflict. Undo restores the original `settings.json` byte-for-byte when it is unchanged; after unrelated edits it removes only unchanged Steer-owned entries and the exact title environment key, preserving other settings and environment formatting. Missing or inconsistent state refuses guessed restoration and leaves targeted manual recovery to the operator.

Automated coverage is in `Tests/SteerCoreTests/ClaudeSetupTests.swift`. It uses temporary roots only; it does not modify the user's Claude or Ghostty configuration. The sanitized isolated startup run record and commands are recorded in [Claude setup live evidence](evidence/claude-setup-live.md). The run record proves that a newly started disposable session delivered the exact-root hook events; existing sessions are intentionally reported as requiring restart. A helper self-test proves both title JSON shapes and the metadata boundary. Ghostty title application, clean SessionEnd reset, and the live old-session restart-required observation remain deferred operator checks; none is claimed as passed here. Those checks also do not prove that project and command-line settings were absent. Claude only delivers `SessionEnd` on supported clean shutdown paths, so reliable abrupt-exit title restoration remains unproven without a launcher or equivalent terminal lifecycle integration.
