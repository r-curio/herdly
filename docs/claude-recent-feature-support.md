# Claude support for recent Steer capabilities

Research resolution for [Establish Claude support for recent Codex features](https://github.com/r-curio/steer/issues/64). Checked 2026-09-16 against Claude Code **2.1.273**. This report identifies candidates and gaps; it does not authorize implementation or reduced parity.

## Evidence boundary

Read-only local checks ran `claude --version`, `claude --help`, subcommand help, `claude agents --json`, process inspection, and bounded binary-string inspection. The installed command returned live `interactive` and `background` entries with full `sessionId`, `cwd`, `name`, `startedAt`, and available `pid`, `status`, `state`, or short background `id`. The observed statuses were `busy` and `idle`; no current tool field was present. The installed binary contains `AskUserQuestion`, `tool_deferred`, `deferred_tool_use`, `five_hour`, and Remote Control tokens, which proves only that those code paths are present.

No model request ran. No transcript, credential, or real Claude/Ghostty/Codex setting was read or changed. One attempted `claude remote-control --help` process was stopped immediately after the documented eligibility-before-help behavior caused it not to return; no session was used.

Prior repo evidence remains relevant: the [event contract](https://github.com/r-curio/steer/blob/1ff97ebe313a542ce7c00cbd5cec2c8508bfe7f3/docs/claude-event-contract.md), [names and usage research](https://github.com/r-curio/steer/blob/92deb6af726d8e68a8ac0f627cc2ae4f0f8f5f91/docs/claude-names-usage.md), [lifecycle proof](https://github.com/r-curio/steer/blob/a5bd06f/docs/claude-lifecycle-proof.md), and [targeting proof resolution](https://github.com/r-curio/steer/issues/36#issuecomment-5693311640). Those live checks used Claude Code 2.1.273 and Ghostty 1.3.1.

## Minimum remaining live experiments

1. **Tool activity:** in disposable settings, record one success, tool failure, companion/native denial, and interrupted running tool; prove the exact rule that clears a working-row action. If no cleanup event exists, clear only on later prompt/stop/session evidence and expose uncertainty rather than retaining a false tool label.
2. **Launch discovery:** start named/unnamed interactive and background sessions before the observer, including busy, waiting, idle, stopped, an alternate `CLAUDE_CONFIG_DIR`, and duplicate resume. Poll `claude agents --json` before/after process exit and Steer restart; correlate only full session IDs and the already-proved exact Ghostty title contract.
3. **Usage:** with disposable status-line configuration, capture sanitized 2.1.273 payloads before the first response, after a response, at independently missing/reset windows, and across the actually used subscription/provider/config roots. Then prove transparent existing-command composition, cancellation, reinstall, and undo.
4. **Questions:** use a disposable `AskUserQuestion` session and a human-selected single choice, multi-choice, and free-text answer. Prove the hook's exact call identity, accepted `updatedInput`, one-shot/late-answer rejection, native fallback on helper failure/timeout, coexistence with another hook, and restart behavior. Do not test by answering for the human.
5. **Follow-ups:** none can establish the missing contract. Do not prototype against keystrokes, transcripts, private daemon files, or `--resume`. Revisit only when Anthropic documents an addressed programmatic reply surface (or the parity decision explicitly removes this capability).

## Decisions changed in downstream tickets

- **Agree Claude parity behavior and capability gaps:** launch-time working/waiting/idle discovery and direct question answers are now real candidates; exact tool text after restart is not. Five-hour and weekly usage may both be shown only when reported. Completion-card follow-up is a material unsupported gap requiring an explicit user disposition.
- **Choose the shared adapter and recovery boundary:** add a read-only Claude inventory adapter around `agents --json`; retain hook normalization for tool/question details and status-line snapshots for usage. Do not parse agent-view state files or introduce a generic control framework. Qualify session identity by agent and treat duplicate live instances as unavailable targets.
- **Agree reversible Claude setup and coexistence:** preview hooks/title plus optional status-line composition, and separately validate the installed `agents --json` schema. Report managed/disabled hooks, agent-view disablement, alternate config roots, and shadowed status line as distinct unsupported states. No setup step may enable Remote Control or alter account policy.
- **Agree the implementation slices and acceptance gates:** split inventory discovery, prospective tool rows, question answering, and optional usage into separately testable vertical slices. Do not create a follow-up-send implementation ticket without a supported transport; carry it as a parity blocker or an explicitly accepted gap. Require installed-version probes and isolated live acceptance for every enabled slice.

## Recommendation

Set the initial runtime floor to the actually evidenced **2.1.273**, then replace that conservative floor only with a tested lower-version matrix. Use native documented surfaces at their narrow boundaries: `agents --json` for discovery, hooks for exact live events and question answers, and status line for usage. The absence of a supported addressed prompt transport is not an invitation to synthesize terminal input or resume a live conversation from a second process.
