# Bind herdr panes when Steer and herdr agree

**Superseded for Codex CLI sessions** by [ADR 0012](0012-bind-codex-herdr-panes-by-title-and-foreground-process.md) on 2026-10-07 (issue #144). Codex runs hooks in a shared daemon whose inherited `HERDR_PANE_ID` taints both signals below. This ADR now governs Claude Code sessions only, and the foreground-process rule was added for them at the same time.

A CLI session in herdr is bound to a pane only when two independent signals agree: Steer's own hook recorded that `HERDR_PANE_ID` (with the default `HERDR_SOCKET_PATH`) in the session's newest event, and herdr's fresh snapshot shows exactly that one pane reporting the session as its `agent_session`. Either signal alone can be stale: herdr never verifies `agent_session` and can restore an old one after a restart, while a hook record only proves the session ran in that pane at some point. Requiring both keeps the binding exact without trusting either source alone.

## Rules

- **Foreground process:** herdr's `pane.process_info` for the bound pane must list the session's own Claude process among its foreground processes, both when binding and again before every Open. This catches a pane where Claude has exited but `agent_session` lingers. The process is the PID that Claude's session registry (`<CLAUDE_CONFIG_DIR>/sessions/<pid>.json`) names as the session's live interactive holder; when Claude recorded the entry's start time (`procStart`), the running process must have started then, so a reused PID never stands in. Any executable name is accepted for that PID. The binding carries no Claude root, so every configured root's latest inventory is searched. Only when no available inventory names the session's process (the one inventory listing the session came from `claude agents --json`, which carries no PID) does the rule fall back to a foreground process named `claude`. When several roots' inventories list the session as interactive, or one root's inventory reports two interactive holders, the binding is unavailable; the name rule is not used instead. Amended 2026-10-08: Claude Code's native installer runs a binary named for its version (`~/.local/share/claude/versions/2.1.293`), which herdr reports as the process name `2.1.293`, so the name rule never matched it. Matching the registry's PID is also stricter than a name: it names this session's process, not any Claude.
- **Duplicates:** two or more panes reporting the session, or a pane whose newest Steer hook event belongs to a different session, leave the session without a binding. Codex hook records are ignored here (ADR 0012).
- **Void binding:** the session ended, herdr reports `null` or another session for the pane, or the herdr server's identity changed since the hook record. After a server restart the binding stays void until a new Steer hook event from that pane. A void binding disables Open and question relay; it never clears attention.
- **Titles veto, never bind:** a pane title shaped like a shortened Codex session identifier that names a different session makes the target unavailable. A missing or free-form title, including every Claude Code title, is ignored.
- **Target checks before every Open or relay:** the bound pane's tab holds exactly one pane (a split or zoomed split is unavailable, as in ADR 0004); the session's socket is herdr's default socket (named sessions are unavailable); the server has exactly one attached client and its ancestry reaches Ghostty (zero, several, or non-Ghostty clients are unavailable).
- **Integration:** `herdr integration status` must report `current (vN)` for `claude`. Codex needs no herdr integration (ADR 0012). Not installed, outdated, or unparseable output is unavailable with guidance toward `herdr integration install <agent>`. Steer never changes herdr configuration.
- **Versions:** herdr protocols are allowlisted, starting with protocol 22 (herdr 0.9.3), and checked before any herdr use. An unlisted protocol disables herdr targeting and relay; hook notifications continue.

## Considered options

- **herdr's `agent_session` only:** unverified and restorable after a restart, so it can point at a pane that no longer runs the session.
- **Steer's hook record only:** cannot tell whether the pane still runs the session after the agent exits or the pane is reused.
- **Match the foreground process by `argv[0]`** (`claude` for a native install): rejected for the same reason ADR 0012 rejects `argv`; a wrapper can set it to anything.

That Steer's hook sees `HERDR_PANE_ID` for Claude Code is inferred from herdr's integration and must be shown live before acceptance. For Codex, the [#116 run](../evidence/herdr-daemon-hook-env.md) showed the hook sees the daemon's inherited value, which led to ADR 0012.
