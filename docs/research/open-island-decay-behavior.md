# Open Island decay behavior

Research for [Research OpenVibe Island decay behavior](https://github.com/r-curio/steer/issues/78).

## Scope and source

The first-party open-source project is [Octane0411/open-vibe-island](https://github.com/Octane0411/open-vibe-island), whose product name is **Open Island**. This note inspects commit [`b50f87a`](https://github.com/Octane0411/open-vibe-island/tree/b50f87aa7d58af1478837d48909eb68baa37f9b9), four metadata-only commits after the latest shipped tag, [`v1.2.1`](https://github.com/Octane0411/open-vibe-island/releases/tag/v1.2.1). The source diff from `v1.2.1` to `b50f87a` changes only `README.md`, `README.zh-CN.md`, and `appcast.xml`, so the behavior below is shipped in v1.2.1 rather than merely proposed on `main`.

Only source, tests, first-party documentation, and the first-party release were used. The repository's watch-notification design documents and roadmap are proposals, so they are not evidence of the macOS app behavior described here.

## Answer

Open Island does **not** use a decay timer as a read receipt. It has three separate mechanisms:

1. A completed notification surface closes after **10 seconds** when the pointer is outside. Hover cancels that timer; after the pointer has entered, leaving closes it. Closing the surface does not change the session state. Approval and question surfaces do not auto-collapse. [The delay is 10 seconds](https://github.com/Octane0411/open-vibe-island/blob/b50f87aa7d58af1478837d48909eb68baa37f9b9/Sources/OpenIslandApp/OverlayUICoordinator.swift#L8-L15), and [the completion-only guard plus hover/leave behavior is explicit](https://github.com/Octane0411/open-vibe-island/blob/b50f87aa7d58af1478837d48909eb68baa37f9b9/Sources/OpenIslandApp/OverlayUICoordinator.swift#L315-L375). The scheduled task only calls `notchClose()` after the guard still holds. [Source](https://github.com/Octane0411/open-vibe-island/blob/b50f87aa7d58af1478837d48909eb68baa37f9b9/Sources/OpenIslandApp/OverlayUICoordinator.swift#L440-L481)
2. A completed row becomes visually stale after a user-selected **2, 5, 10, or 20 minutes, or never**; the default is **5 minutes**. This does not delete it or alter `SessionPhase.completed`: it moves to the low-priority Idle presentation. [Preference and exact values](https://github.com/Octane0411/open-vibe-island/blob/b50f87aa7d58af1478837d48909eb68baa37f9b9/Sources/OpenIslandApp/AppModelTypes.swift#L56-L64), [threshold enum](https://github.com/Octane0411/open-vibe-island/blob/b50f87aa7d58af1478837d48909eb68baa37f9b9/Sources/OpenIslandApp/AppModelTypes.swift#L103-L120), [state-preserving presentation rule](https://github.com/Octane0411/open-vibe-island/blob/b50f87aa7d58af1478837d48909eb68baa37f9b9/Sources/OpenIslandApp/AgentSession%2BPresentation.swift#L351-L359), [user-facing wording](https://github.com/Octane0411/open-vibe-island/blob/b50f87aa7d58af1478837d48909eb68baa37f9b9/Sources/OpenIslandApp/Resources/en.lproj/Localizable.strings#L97-L103)
3. A session disappears when its source lifecycle says it is no longer visible, not because the user read it. Actionable states remain visible; hook-managed sessions remain visible until ended; process-managed sessions remain visible while their process is alive. Reconciliation then removes invisible sessions from in-memory state. [Visibility contract](https://github.com/Octane0411/open-vibe-island/blob/b50f87aa7d58af1478837d48909eb68baa37f9b9/Sources/OpenIslandCore/AgentSession.swift#L555-L573), [removal](https://github.com/Octane0411/open-vibe-island/blob/b50f87aa7d58af1478837d48909eb68baa37f9b9/Sources/OpenIslandCore/SessionState.swift#L525-L533)

The list reevaluates age every **30 seconds**, so a row can cross its configured threshold up to one refresh after the exact instant. [Refresh cadence](https://github.com/Octane0411/open-vibe-island/blob/b50f87aa7d58af1478837d48909eb68baa37f9b9/Sources/OpenIslandApp/Views/IslandPanelView.swift#L552-L595) Independently, non-running, non-attention detail lines collapse and the session becomes presentation-inactive after **20 minutes**. [Detail and presence rules](https://github.com/Octane0411/open-vibe-island/blob/b50f87aa7d58af1478837d48909eb68baa37f9b9/Sources/OpenIslandApp/AgentSession%2BPresentation.swift#L301-L359) These are also visual changes, not state transitions.

## Persistence and restart

Open Island persists recent session presentation records, including phase, summary, and update time, but not live permission or question payloads. [Claude record fields](https://github.com/Octane0411/open-vibe-island/blob/b50f87aa7d58af1478837d48909eb68baa37f9b9/Sources/OpenIslandCore/ClaudeSessionRegistry.swift#L3-L13) [Record conversion](https://github.com/Octane0411/open-vibe-island/blob/b50f87aa7d58af1478837d48909eb68baa37f9b9/Sources/OpenIslandCore/ClaudeSessionRegistry.swift#L39-L73) On startup it restores and retains only records updated in the last **24 hours**, pruning older records. [Startup cutoff and prune](https://github.com/Octane0411/open-vibe-island/blob/b50f87aa7d58af1478837d48909eb68baa37f9b9/Sources/OpenIslandApp/SessionDiscoveryCoordinator.swift#L93-L153) Persistence itself also filters to 24 hours. [Persistence filter](https://github.com/Octane0411/open-vibe-island/blob/b50f87aa7d58af1478837d48909eb68baa37f9b9/Sources/OpenIslandApp/SessionDiscoveryCoordinator.swift#L540-L570)

Startup restore assigns state directly rather than replaying `sessionCompleted`, `permissionRequested`, or `questionAsked` events, so it does not establish a fresh notification or a live actionable connection. Older-than-24-hour removal is cache retention, not read evidence. Because the record has no read, acknowledged, or expired field, none of the timers can carry those meanings.

## What transfers safely to Steer

- Treat **notification-surface auto-collapse** as presentation-only. A 10-second card can close without clearing the underlying attention item.
- If desired, use an explicit **visual decay** for old outcomes: keep the outcome identity intact, retain Open/Dismiss, and move it to a lower-priority presentation after a configurable threshold. Open Island's default is 5 minutes, but its options show the policy is preference, not truth.
- Pause or cancel presentation decay while the pointer is interacting with the card.
- Let exact source resolution remove approval/question controls. A timer may mark controls expired or unavailable, but must not mark them read or approved.
- Restore cached presentation separately from live interaction state and suppress replay notifications on startup.

## What conflicts with Steer's exact-evidence model

- Treating Open Island's 10-second auto-collapse as acknowledgment or evidence the result was read.
- Clearing the underlying completion/reminder when the completed row becomes Idle at 2/5/10/20 minutes.
- Treating source disappearance, process death, hook timeout, or the 24-hour cache cutoff as read evidence.
- Copying Open Island's undifferentiated `.completed` model for success, failure, denial, and interruption. Steer needs to retain the actual outcome and uncertainty because a summary string is not a reliable state contract.
- Restoring a waiting phase as actionable when the exact live request and response channel were not restored.

## Bottom line for the pending Steer decision

Open Island supports a safe precedent for **decaying presentation, not truth**: auto-collapse the transient completion spotlight, then optionally lower the visual priority of the durable outcome. It provides no precedent for auto-acknowledging or deleting an unseen completion. Steer should continue to clear outcome attention only on explicit dismissal or exact read evidence; if it adds decay, record it as `expired`/low-priority presentation and preserve safe actions rather than calling it read.
